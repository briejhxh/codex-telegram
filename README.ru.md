# Codex Telegram

[English version](README.md)

`codex-telegram` — локальный сервер [Model Context Protocol](https://modelcontextprotocol.io/) и плагин Codex для **личного аккаунта Telegram**. Он использует TDLib/MTProto, а не Bot API и не автоматизацию браузера.

Сервер работает на вашем компьютере. Учётные данные Telegram API, база TDLib, авторизационная сессия и загруженные медиафайлы хранятся в приватной папке пользователя и не передаются сторонним сервисам этим проектом.

> **Статус:** ранний релиз. Для разработки используйте отдельный Telegram-аккаунт, а сценарии с отправкой сначала проверяйте в «Избранном».

## Возможности

- Просмотр сведений об аккаунте, чатов, непрочитанных сообщений и истории с постраничной загрузкой.
- Диагностика локальной конфигурации, сессии TDLib и проблем авторизации без раскрытия секретов.
- Поиск чата по имени или `@username`, указание точных совпадений и чтение закреплённого сообщения.
- Поиск чатов и сообщений, включая контакты и публичные username.
- Поиск документов, медиа, голосовых сообщений и ссылок в конкретном чате без скачивания.
- Отправка сообщений и ответов, загрузка и скачивание выбранных файлов.
- Просмотр inline-клавиатур ботов и нажатие безопасных callback-кнопок.
- Добавление и удаление явно подтверждённой emoji-реакции.
- Редактирование и удаление только сообщений, отправленных авторизованным аккаунтом, с явным подтверждением.
- Хранение секретов и состояния TDLib вне репозитория по умолчанию.

Сервер намеренно **не** нажимает URL-, login-, web-app-, game-, payment- и password-кнопки. Он не сканирует Telegram Web и не запрашивает ID аккаунтов или контактов у сторонних ботов.

## Требования

- Node.js 20 или новее.
- `pnpm` 9 или новее (`corepack enable` включает версию, поставляемую с Node.js).
- Telegram `api_id` и `api_hash` из [my.telegram.org](https://my.telegram.org).
- Codex Desktop — если нужен интерфейс плагина.

## Установка с GitHub

```powershell
git clone https://github.com/aagafon1215-source/codex-telegram.git
cd codex-telegram
corepack enable
pnpm install --frozen-lockfile
pnpm run check
pnpm run setup
pnpm run login
```

`pnpm run setup` запросит Telegram API ID и hash и сохранит их в пользовательском конфигурационном файле. Учётные данные не записываются в клон репозитория. `pnpm run login` запросит номер телефона, код Telegram и, при наличии, пароль двухфакторной аутентификации.

В Windows состояние хранится в `%LOCALAPPDATA%\codex-telegram`; в macOS/Linux — в `~/.local/state/codex-telegram`. Чтобы выбрать другое место, задайте `TG_CONFIG_DIR` до запуска setup. Также можно задать абсолютные пути `TG_CONFIG_FILE`, `TG_DATABASE_DIR`, `TG_FILES_DIR` и `TG_DOWNLOADS_DIR`. Явно загружаемые файлы принимают только имя файла, сохраняются внутри `TG_DOWNLOADS_DIR` и не перезаписывают существующие. По умолчанию размер загрузки ограничен 100 MiB; изменить лимит можно положительным значением в байтах через `TG_MAX_DOWNLOAD_BYTES`.

Только для локальной разработки поддерживается копирование `.env.example` в `.env`. Чтобы включить его загрузку, укажите `TG_USE_DOTENV=1`: это не позволяет клону репозитория незаметно стать местом хранения Telegram-сессии. Никогда не коммитьте этот файл.

Если в старом клоне API-данные были записаны в `.env`, один раз выполните `pnpm run migrate-legacy-config`. Команда переносит только API-данные в приватный конфигурационный файл и не перезаписывает существующий; затем выполните `pnpm run login`, чтобы создать сессию в приватной папке состояния.

## Подключение к Codex

Репозиторий содержит локальный исходник плагина. После установки зависимостей и сборки добавьте клон через свой локальный marketplace/plugin workflow в Codex. MCP-манифест использует переносимые настройки:

```json
{ "command": "node", "args": ["dist/index.js"], "cwd": "." }
```

Codex запускает сервер сам; не запускайте `pnpm start` одновременно. TDLib допускает только один процесс, использующий одну базу сессии. После установки или обновления плагина откройте новую задачу Codex.

Если `node` или `pnpm` недоступен, потому что установлен только Codex Desktop, используйте Windows-скрипт `scripts/run-with-codex-runtime.ps1`:

```powershell
.\scripts\run-with-codex-runtime.ps1 setup
.\scripts\run-with-codex-runtime.ps1 login
.\scripts\run-with-codex-runtime.ps1 build
```

## Модель безопасности инструментов

Инструменты чтения не изменяют данные. `telegram_send_message`, `telegram_reply_message` и `telegram_send_file` меняют внешнее состояние; включённый навык Codex требует явного указания получателя и подтверждения точного текста перед их вызовом.

`telegram_click_inline_button` также может изменить состояние бота. Его можно использовать только после явного разрешения пользователем нужного сценария кнопки. Инструмент принимает только callback-кнопки и отказывает для кнопок высокого риска.

`telegram_edit_own_message` и `telegram_delete_own_message` работают только с исходящими сообщениями авторизованного аккаунта. Оба требуют подтверждения; удаление помечено как разрушительное действие и просит Telegram удалить сообщение у всех, когда это допускает Telegram.

Если Telegram недоступен, начните с `telegram_health`. Инструмент показывает только безопасный локальный статус, фактические локальные пути TDLib и подсказку по исправлению; API-данные, коды входа и текст сообщений в него не попадают. Заблокированная сессия определяется за ограниченную 15-секундную попытку подключения.

Плагин возвращает только данные, запрошенные инструментом. Не просите его вставлять в задачу большие приватные истории и не публикуйте в чате коды входа Telegram или учётные данные API.

## Разработка

```powershell
pnpm run typecheck
pnpm run test
pnpm run build
pnpm run check
```

Вручную запускайте сервер только при разработке MCP-клиента:

```powershell
pnpm start
```

Логи пишутся в stderr, чтобы stdout оставался корректным MCP JSON-RPC.

## Чек-лист релиза

1. Выполните `pnpm install --frozen-lockfile && pnpm run check`.
2. Выполните `pnpm run plugin:validate`.
3. Убедитесь, что `git status --ignored` не показывает учётных данных, базу TDLib, скачанные файлы или результат сборки `dist/`.
4. Прочитайте [`SECURITY.md`](SECURITY.md) и [`docs/PRIVACY.md`](docs/PRIVACY.md).
5. Создавайте версионный тег только после проверки входа и инструмента чтения на тестовом аккаунте.
